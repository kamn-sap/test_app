# 🧪 8. テスト戦略

このプロジェクトで実装されているテストと、実行方法をまとめます。記載内容は現在の `backend/build.gradle` と `frontend/package.json` に基づいています。

## テスト構成

| 対象 | ツール | 実装・コマンド |
|---|---|---|
| バックエンド | Spring Boot Test / JUnit Platform | `cd backend && ./gradlew test` |
| バックエンドカバレッジ | JaCoCo 0.8.12 | `./gradlew jacocoTestReport` |
| フロントエンド単体テスト | Vitest 3.2.3 / jsdom | `cd frontend && npm run test:unit` |
| フロントエンドカバレッジ | `@vitest/coverage-v8` | `npm run test:unit` |
| E2E | Playwright 1.52.0 | `cd frontend && npm run test:e2e` |
| E2E レポート | Allure Playwright / Playwright HTML | `npx allure generate ...` / `npx playwright show-report` |

> このリポジトリでは、テスト管理サービス（Qase など）や SonarQube は使用していません。

## 前提条件

ローカルで E2E を実行する場合は、アプリケーションを起動しておきます。

```bash
cd infra
docker compose -f docker-compose.local.yml up -d --build
```

バックエンドの単体テスト・カバレッジだけを実行する場合は、Docker Compose は必須ではありませんが、テストで利用する設定に応じた Java 環境が必要です。

## バックエンドテスト

```bash
cd backend

# テストを実行
./gradlew test

# JaCoCo レポートを生成
./gradlew jacocoTestReport
```

レポートは `backend/build/reports/jacoco/test/html/index.html` に生成されます。

`build.gradle` では `check` 実行時に JaCoCo のカバレッジ検証も実行し、命令網羅率 80% を下限として設定しています。

### E2E カバレッジ

E2E 実行時に生成された `infra/jacoco-output/jacoco.exec` が存在する場合、次のタスクで利用できます。

```bash
cd backend
./gradlew jacocoE2EReport
```

## フロントエンド単体テスト

```bash
cd frontend
npm install
npm run test:unit
```

ウォッチモードで実行する場合:

```bash
npm run test:unit:watch
```

## E2E テスト

初回のみ Playwright のブラウザをインストールします。

```bash
cd frontend
npm install
npm run setup:e2e
npm run test:e2e
```

特定のテストファイルを実行する場合:

```bash
npx playwright test tests/e2e/login.spec.ts
```

`playwright.config.ts` に定義されたプロジェクトや実行条件を基準にしてください。存在しない npm script（例: `test:headless`、`test:allure`、`setup:agents`）は使用しません。

## レポート

Playwright 標準レポート:

```bash
cd frontend
npx playwright show-report
```

Allure レポート:

```bash
cd frontend
npx allure generate allure-results --clean -o allure-report
npx allure open allure-report
```

E2E とフロントエンドカバレッジを続けて実行する場合:

```bash
npm run test:e2e:coverage
```

## CI

CI では `infra/docker-compose.ci.yml` を使用します。CI 用の AWS 互換サービスは LocalStack ではなく Moto (`motoserver/moto:latest`, port 5000) です。

E2E の CI ワークフローは `.github/workflows/e2e.yml` を参照してください。CI の実行条件や成果物の扱いは、ワークフローの実装を正とします。

## テスト追加時の確認事項

- 実際に存在する npm script または Gradle task を使用する
- E2E ではローカルサービスを起動し、フロントエンドとバックエンドの接続を確認する
- AWS S3 のローカルエミュレーションには Moto を使用する
- カバレッジの目標値を実績値と混同しない
- テスト管理サービスや SonarQube の設定を追加する場合は、実装と CI の変更を先に行う
